Fix Render build: .dockerignore excluded the files the Dockerfile copies

Commit 3ac6912 made the Dockerfile copy dist/NovaCore-Setup-1.0.0.exe,
dist/novacore-local-search-1.0.0-x64.nsis.7z, dist/latest.yml and
downloads/app-debug.apk, but .dockerignore still listed "dist" and "*.exe".
The build context therefore never contained those paths, so Render stopped at
the COPY step in 9 seconds.

- .dockerignore: rewritten with explicit comments. dist/ and downloads/ are
  now part of the build context (they are what the download routes serve);
  only genuine non-runtime paths are excluded (node_modules, android, api,
  deploy-gate, tests, docs, .git). Excluding .md files no longer risks icons.
- Dockerfile: removed a duplicated COPY block; added a chmod so the
  downloads are readable after USER node (a 0600 copy would answer 500).
- server.js: an unreadable download (EACCES) now answers 404 with a logged
  reason instead of a bare 500, and a stream that fails before any bytes are
  sent answers JSON instead of dropping the socket. Dockerfile and
  .dockerignore are part of the local diagnostics file list.
- docker-context.test.js: evaluates .dockerignore against every Dockerfile
  COPY source (and requires each file to be committed). It fails on the
  3ac6912 .dockerignore and passes on this one, so the exact Render failure
  cannot ship silently again.

Keep unchanged: renderer.js, MainActivity and the installer stub still point
at https://novacore-0ik3.onrender.com, and the payload archive the stub
downloads is served from /dist/ by the same image.

Verification: npm run check; npm test 32/32; deploy-gate/docker-image-check
(simulated /app starts as USER node and serves /app-setup.exe + /app-debug.apk);
download-routes-check (all six routes return real bytes, including the 93 MB
installer payload and latest.yml).
